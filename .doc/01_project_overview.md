# 01. 프로젝트 개요 및 NPU 기초 이론 (Project Overview & Theory)

## 1. NPU(Neural Processing Unit)란 무엇인가?

### 1.1 연산 처리 장치의 진화 (CPU vs GPU vs NPU)
현대 컴퓨팅 환경에서 인공지능(AI) 모델과 딥러닝 알고리즘이 대중화됨에 따라, 데이터를 처리하는 프로세서의 구조도 크게 진화해 왔습니다.

```
+-----------------------------------------------------------------------------+
| [CPU (중앙 처리 장치)]                                                      |
| - 복잡한 제어 로직, 분기 예측, 대용량 캐시 메모리 중심                      |
| - 직렬 연산(Single/Few Thread)에 최적화 -> 행렬 대량 연산 시 비효율         |
+-----------------------------------------------------------------------------+
                                     ↓
+-----------------------------------------------------------------------------+
| [GPU (그래픽 처리 장치)]                                                    |
| - 수천 개의 소형 코어로 대규모 병렬 처리(SIMD/SIMT) 수행                   |
| - 그래픽 렌더링 및 범용 병렬 연산에 우수하나 전력 소모와 하드웨어 비용이 큼 |
+-----------------------------------------------------------------------------+
                                     ↓
+-----------------------------------------------------------------------------+
| [NPU (신경망 처리 장치)]                                                    |
| - 딥러닝의 90% 이상을 차지하는 **MAC(곱셈-누적) 행렬 연산**에 완전 특화    |
| - 시스톨릭 어레이(Systolic Array) 구조로 데이터 재사용 극대화 및 초저전력   |
+-----------------------------------------------------------------------------+
```

### 1.2 왜 NPU 시뮬레이터를 순수 코드로 작성해보아야 하는가?
딥러닝 프레임워크(PyTorch, TensorFlow)나 라이브러리(NumPy)를 사용하면 단 한 줄의 함수 호출(`torch.matmul`, `np.dot`)로 행렬 연산이 수행됩니다. 하지만 이는 하드웨어 내부에서 실제로 어떤 비트와 데이터가 곱해지고 더해지는지 추상화하여 감춥니다.

본 프로젝트는 **외부 라이브러리를 일체 배제(Zero-Dependency)**하고, 순수 Python 언어의 기본 구조(2중 루프, 기본 자료형)만을 사용하여 NPU 내부의 핵심 산술 유닛인 **MAC 유닛의 동작 원리**를 밑바닥부터 시뮬레이션합니다.

## 2. MAC(Multiply-Accumulate, 곱셈-누적 연산)의 본질

### 2.1 수학적 정의
**MAC 연산**은 딥러닝의 합성곱(Convolution)과 완전 연결층(Fully Connected Layer)의 근간을 이루는 기본 연산입니다. 두 개의 피연산자를 곱한 뒤, 기존의 누적기(Accumulator) 레지스터 값에 더하는 과정입니다:

$$\text{Accumulator} \leftarrow \text{Accumulator} + (A \times B)$$

2차원 $N \times N$ 격자(Grid) 데이터에 대해 패턴(입력 데이터)과 필터(가중치 커널) 간의 유사도를 측정하는 MAC 연산 수식은 다음과 같습니다:

$$\text{Score} = \sum_{r=0}^{N-1} \sum_{c=0}^{N-1} \left( \text{Pattern}[r][c] \times \text{Filter}[r][c] \right)$$

- $r$: 행 인덱스 ($0 \le r < N$)
- $c$: 열 인덱스 ($0 \le c < N$)
- $\text{Pattern}[r][c]$: 입력 데이터의 특정 좌표 값
- $\text{Filter}[r][c]$: 템플릿 필터(특징 커널)의 특정 좌표 가중치

### 2.2 패턴 유사도 매칭의 원리
- **필터(Filter)**는 NPU가 찾고자 하는 "이상적인 특징(Feature)"의 형태를 가중치로 저장한 템플릿입니다.
  - 예: `Cross 필터`는 십자가 형태 위치에 양수 가중치를 배치합니다.
  - 예: `X 필터`는 대각선 형태 위치에 양수 가중치를 배치합니다.
- **입력 패턴(Pattern)**이 특정 필터의 형태와 일치할수록, 0이 아닌 유효한 값끼리 서로 곱해져 누적 점수($\text{Score}$)가 커집니다.
- 최종적으로 **가장 높은 MAC 점수를 획득한 필터**의 라벨을 입력 데이터의 예측 결과로 판정합니다.

## 3. 프로젝트 주요 설계 원칙과 제약조건

1. **외부 라이브러리 일체 미사용 (Zero External Library)**
   - `NumPy`, `SciPy`, `Pandas` 등 고성능 C 확장 라이브러리를 사용하지 않고 Python 내장 표준 라이브러리(`json`, `time`, `os`, `sys`)만 사용합니다.
   - 이를 통해 메모리 인덱싱, 2중 중첩 루프, 부동소수점 오차 등 로우레벨 알고리즘의 동작 인과관계를 투명하게 관찰할 수 있습니다.

2. **부동소수점 허용오차(Epsilon) 기반의 엄격한 판정**
   - 컴퓨터의 2진 부동소수점(IEEE 754) 연산 특성상 발생하는 미세한 오차($0.1 + 0.2 \neq 0.3$)로 인해 단순 `>` 또는 `==` 연산자는 오작동할 수 있습니다.
   - 따라서 $\epsilon = 10^{-9}$ 기준의 허용오차 비교 정책을 적용하여 수치적으로 완전한 동점(UNDECIDED)을 정확히 검출합니다.

3. **이질적인 데이터셋의 라벨 정규화 (Normalization)**
   - 외부 파일(`data.json`)에 정의된 `'+'`, `'x'`, `'cross'`, `'X'` 등 다양한 형태의 라벨 표기를 내부 표준 형태(`'Cross'`, `'X'`)로 일관되게 변환하여 판정 파이프라인의 견고성을 확보합니다.

4. **$O(N^2)$ 복잡도 실측 및 하드웨어 가속 필요성 증명**
   - 크기 $N$이 커짐에 따라 순차적 2중 루프의 연산 소요 시간이 2차 곡선형($N^2$)으로 급증하는 현상을 벤치마크로 확인하고, 대규모 행렬을 1 클럭에 처리하는 하드웨어 NPU의 필요성을 이론적으로 고찰합니다.
